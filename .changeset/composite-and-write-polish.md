Four tool fixes from the v0.11.0 review. `generate_alert_insights_report` no longer fails its `changes` section with `RB_LIMIT_QUERY` when `change_lookback_hours` plus `before_minutes` reach past the connection's window limit: the range is clamped, with a note. Every composite report (`generate_alert_insights_report`, `entity_health`, `dependency_health`) now adds a top-level note naming the incomplete sections whenever `partial` is true. `create_dashboard`: errors raised locally show their details as plain text, the multi-statement hint is about widget queries, a query that does not start with `SELECT` or `FROM` is refused, a query without `SINCE` produces a warning, and `dry_run` syntax-checks each widget query (at most 10, `LIMIT 1` over the last 5 minutes, paid from the request budget) and reports the result per widget in `checks`; it still never creates anything. `list_change_events(entity_guid)` now lists the entity's other change-tracking events (feature flags, configuration changes, markers from `create_change_event`) next to its deployments. `trace_error(error_group_id)` matches a group message that has New Relic placeholders (`<NUMBER>`, `<UUID>`) with `LIKE`, instead of falling back to "matched on class only".
