> section 4a gives each one a status, the code and tests that prove it, and its residual or accepted risk; the

## 1. Scope and trust boundaries

```
[Internet] ──TLS──▶ [relic-bridge HTTP edge] ──▶ [core] ──TLS──▶ [NerdGraph]
     ▲                    │        │
     │                    ▼        ▼
[MCP client + LLM]    [storage]  [IdP: Google/GitHub/CF Access]
     ▲
[telemetry content written by third parties: logs, error messages, span names]
```

Trust boundaries:
- **TB1** MCP client → server (authentication and authorization)
- **TB2** server → storage (secrets at rest)
- **TB3** server → NerdGraph (outbound credentials)
- **TB4** admin browser → admin panel
- **TB5** telemetry content → LLM: data returned by tools is **untrusted**
- **TB6** supply chain → build artifacts

## 2. Assets

| Asset | Sensitivity | Notes |
|---|---|---|
| NR User API keys | **critical** | Can read all telemetry the NR user can see; may also allow writes on the NR side. |
| Master encryption key (`RB_MASTER_KEY`) | **critical** | Decrypts all credentials. |
| Access tokens / OAuth tokens / refresh tokens | high | Each one gives access to one project grant. |
| Admin sessions | high | Full control of the instance. |
| Telemetry query results | high | May contain PII, secrets in logs, customer data. |
| Audit log | medium | Contains NRQL (redacted) and usage metadata. |
| Configuration (projects, grants) | medium | Reveals structure; no secrets. |

## 3. Threat actors

1. Unauthenticated internet attacker (remote modes).
2. Authenticated client trying to exceed its grant (other project, tool or account).
3. **Malicious telemetry author**: anyone who can make the monitored apps log text (prompt injection).
4. Malicious or compromised MCP client or OAuth client registration.
5. Rogue or compromised admin.
6. Supply-chain attacker (dependency, GitHub Action, release pipeline).
7. Local malware on a user's device (out of scope beyond token revocation and short token lifetimes).

## 5. Security requirements checklist (non-negotiable)

Ticked in v1 with the evidence that holds each item today.

- [x] MCP and admin routes require a credential in remote modes. The unauthenticated surface is exactly `/health`,
  `/version`, `/.well-known/*`, `/admin/assets/*`, the sign-in routes `/auth/*`, the OAuth endpoints
  `/oauth/{authorize,token,register}` (per-IP limited), and, only with `RB_PUBLIC_TOOL_CATALOG=on`, discovery
  (`initialize`, `tools/list`) on `POST /p/:slug/mcp` (T33); the opt-in `/passthrough/mcp` authenticates with the
  caller's New Relic key. Pinned by the route-table guard in `packages/http-app/test/authz/routes.test.ts` (Hono's route
  table must equal `matrix.ts`).
- [x] Read-only by default; any tool with side effects is `annotations.readOnlyHint=false` and disabled by default
  (`tool.ts` `annotationsFor`, `ToolRegistry` `allowNonRead`, `RB_WRITE_TOOLS` off on every host; T6, T31).
- [x] Known secret shapes are redacted at every sink (logs, errors, audit, tool output, telemetry), and values without a
  shape are never logged (T8: pattern-based, its residual is stated there).
- [x] Every value sent to NerdGraph travels as a **GraphQL variable**; values embedded in NRQL templates go through the
  `nrql` tag / `nrql.identifier()` (P1-02, P1-04; lint-enforced as a heuristic, property-tested in P8-01; T4).
- [x] No module-level mutable state holds request credentials or grants (P8-01 sweep of `packages/*/src` and
  `apps/*/src`, T21; held by review, not by a lint).
- [x] No MCP tool accepts a secret as an argument or manages credentials (T23).
- [x] Every new endpoint has authz tests, including negative cases (admin API: P2-09; consolidated suite P2-12, whose
  guard tests fail when a route or a built-in read tool lacks its cases; write tools are covered by loops over
  `WRITE_TOOL_NAMES`; prompts and resources have grant tests without a guard).
- [x] Docs explain the prompt-injection risk and the read-only default ([security basics](guide/security-basics.md),
  [output formats](guide/output-formats.md), README, SECURITY.md).
