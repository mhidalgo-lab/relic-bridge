# P1-07 — Tools: whoami, list_accounts, time_range

## Scope
- `whoami` (read, `group: identity`, no inputs except `mask_email?`): NR user id / name / email (email masked on
  request, e.g. `m***@example.com`), region, project slug, default account, reachable-and-allowed account count,
  allowed tool names and the effective query limits. Never returns key material. Project slug and allowed tools come
  from an optional `ToolContext.connection` (`{ project?, allowedTools? }`) that the stdio CLI (P1-11) and Phase 2
  fill in; absent values are reported as unknown.
- Key validation passes `actor.accounts(scope:)` explicitly (`RegionScope`, `IN_REGION`: the key's own data center),
  as a GraphQL variable. `IDENTITY_QUERY` is updated, and a lighter accounts-only document is added.
- `list_accounts` (read, `group: identity`): accounts reachable **and allowed** (intersection of the key's accounts
  and `ctx.accounts.allowed`), default marked; allowed-but-unreachable ids are reported as a note. Account names are
  New Relic data and go inside the untrusted-data envelope.
- `time_range { expression }` (read, `openWorld: false`, cost 0, `group: time`): pure function (no subrequest) turning
  "last 2 hours", "past 30 minutes", "today", "yesterday", "this week", "last week", ISO instants / dates and
  "<start> to <end>" ranges into `since_ms`, `until_ms` (epoch ms, UTC), `window_ms` and an NRQL `SINCE … UNTIL …`
  clause. Uses `ctx.clock`. Warns when the window exceeds the connection's `maxWindowDays`.

## Acceptance criteria
- [x] Tests incl. account intersection (credential reaches 3, project allows 2 → 2 listed; allowed id not reachable is
      noted, never listed).
- [x] `whoami`: masked and unmasked email, no key material in text or structured output, unknown project/tools
      reported as such; output validates against its schema.
- [x] Identity request passes `scope` as a variable (no string interpolation).
- [x] `time_range`: relative, calendar and ISO inputs, bad input rejected with `RB_INPUT_INVALID`, no subrequest spent.
- [x] Listing: all three tools `readOnlyHint: true`; `time_range` has `openWorldHint: false`.
- [x] Negative tests: account names with injection text stay inside the envelope; strict inputs reject unknown
      arguments; exhausted budget sends no request.

## Security notes
T3 (account filtering: listing never shows an account the project does not allow), T6 (account names and user
name are untrusted data), T8 (no key material).
