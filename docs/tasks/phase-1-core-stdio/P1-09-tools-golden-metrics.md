# P1-09 — Tool: get_golden_metrics

## Scope
- `get_golden_metrics { guid, since?, timeseries?, max_metrics? }`: fetch `entity.goldenMetrics { metrics { title query } }`
  for one entity (GUID decoded and its account checked offline before any request), run each query in the entity's
  account, and return a compact health summary per metric: latest value, trend direction (up/down/flat/unknown from a
  time series) and the NRQL that was run.
- `since` is a `parseTimeRange` expression (default "last 30 minutes"). The time clause is appended only when the
  golden query has no top-level SINCE/UNTIL; `TIMESERIES AUTO` only when `timeseries` is true (default) and the query
  has none. Faceted results are reported without a trend (point to `run_nrql`).
- Golden-metric NRQL comes from New Relic, not from the agent, so it runs through a new engine entry point
  (`runTrustedNrql`) that skips the raw-NRQL switch but still enforces query limits (window, LIMIT, length).
- Budget-aware: only as many metrics as the remaining budget allows are started (parallel, within the limiter); the
  rest are reported as `skipped`. A per-metric failure (limit, timeout, syntax) is reported on that metric; credential
  and authorization failures abort the whole call.
- Out of scope: charts, comparing against a baseline period, alert thresholds.

## Acceptance criteria
- [x] Fixture tests incl. partial result under small budget.
- [x] Negative authorization tests (other-account GUID refused offline; entity returned from a non-allowed account refused).
- [x] Trend maths and clause handling covered by unit tests; golden NRQL still passes query limits.

## Security notes
Golden-metric NRQL comes from New Relic, not the client, but still passes through limits (time window, LIMIT). Titles
and values are New Relic data: inside the untrusted-data envelope.
