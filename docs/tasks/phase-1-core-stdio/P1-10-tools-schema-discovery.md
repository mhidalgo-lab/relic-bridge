# P1-10 — Tools: schema discovery

## Goal
Let agents write *correct* NRQL by discovering what data exists.

## Scope
- `list_event_types { account?, since? }`: the event types with data in one account (SHOW EVENT TYPES). `since` is a
  `parseTimeRange` expression (default "last 24 hours"); one account per call (default account when omitted, must be allowed).
  Connection event-type limits apply: a deny list is filtered out of the result; with an allow list the query is not
  sent and the allow list itself is returned (SHOW EVENT TYPES names no type, so it would be refused).
- `get_attributes { event_type, account?, since?, sample? }`: the attribute names and types seen on one event type
  (keyset()), plus an optional one-row sample (`sample: true`, default false) in an untrusted-data envelope. `event_type`
  goes through `nrql.identifier()`; `since` default "last 24 hours"; named types still pass the event-type limits.
- Server-built queries (nrql tag, `runNrql`): not gated by `rawNrql`; query limits still apply. Time clauses are
  built from integers ("N seconds ago").
- Both results are cached per tool-set instance for 5 minutes (bounded map keyed by credential id, region, account,
  event type, `since` text); the sample is never cached.
- Counts per event type are out of scope (one query per type; use `run_nrql`).

## Acceptance criteria
- [x] Event type validated via `nrql.identifier()`; tests (injection attempts, charset).
- [x] Fixture tests: list, deny/allow lists, keyset result shapes, sample envelope, cache hit/expiry/isolation.
- [x] Negative authorization tests: account outside the grant refused, no request sent; cache not shared across credentials.
- [x] Attribute names and sample values are inside the untrusted envelope.

## Security notes
T4, T6, T21 (cache keying). Attribute names and sample values are customer data: untrusted.
