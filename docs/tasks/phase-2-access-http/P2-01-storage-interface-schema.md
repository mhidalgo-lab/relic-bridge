# P2-01 — Storage interface, Drizzle schema and migrations

## Scope
- `packages/storage` (web-standard APIs only, ADR-0004):
  - `Storage` interface with async repositories: `users`, `credentials`, `projects`, `grants`, `accessTokens`,
    `auditLog`, `settings`, `kv`. Records, inputs and errors (`NotFoundError`, `ConflictError`,
    `ReadOnlyStorageError`) are adapter-agnostic.
  - The schema covers all of Phase 2 so P2-03/04/05/08 need no disruptive migration: encrypted key columns
    (ciphertext, IV, key version, last-4 hint) for P2-03, credential validation state and revocation for P2-04,
    token hash/prefix/expiry/`last_used_at`/revocation for P2-05, audit fields for tool calls and admin actions for
    P2-08, a KV-compatible table for the Node OAuth adapter (ADR-0009), and a settings table.
  - Drizzle schema (SQLite dialect) in `src/schema.ts`, separate entry point `@relic-bridge/storage/schema`.
  - SQL migrations generated by drizzle-kit and committed (`packages/storage/migrations/`), embedded into
    `src/migrations.generated.ts` (Workers can't read files) with a lint check that they stay in sync.
  - A forward-only migration runner over a minimal SQL driver interface, tracked in `schema_migrations`
    (`version`, `name`, `applied_at`); each migration and its bookkeeping row are applied atomically.
  - In-memory adapter (`createMemoryStorage`) implementing the full interface (tests, ephemeral use), enforcing the
    same uniqueness and referential rules as the SQL schema.
  - Shared contract suite `runStorageContract(options)` (entry `@relic-bridge/storage/testing`): read paths over a
    seeded fixture for every adapter; write paths, constraints, append-only audit and KV expiry for writable
    adapters; read-only adapters must refuse every write with `ReadOnlyStorageError`.
  - `yaml` adapter (`createYamlStorage`), read-only: the YAML config schema and parser move from `apps/cli` to
    `packages/storage`; each YAML project becomes a project plus a credential whose key is a reference
    (`${ENV}` or an inline literal), never copied into a plain field. `apps/cli` reads its project through the
    `Storage` interface; user-visible behaviour and messages are unchanged.

## Acceptance criteria
- [x] Contract suite passes for `yaml` (read paths, writes refused) and the in-memory adapter (everything).
- [x] Migrations are forward-only and idempotent: tested against a real SQLite engine (`node:sqlite`, test only):
      applying twice is a no-op, a database newer than the code is refused, a failing migration leaves no partial
      state, and the migrated tables match the Drizzle schema (no drift).
- [x] Secrets only as ciphertext columns (no plaintext key column anywhere); tokens only as SHA-256 hashes;
      audit log has no update/delete API except retention purge.
- [x] `apps/cli` tests pass unchanged in behaviour.

## Security notes
T7 (ciphertext columns only), T17 (audit append-only: no update/delete API except retention job), T1/T15 (tokens
stored as hashes), T21 (no module-level state in adapters).
